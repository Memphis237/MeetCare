# BUSINESS PLAN - MEETCARE - SPRINT 2

## 1. Résumé exécutif
**MeetCare** est une application de bureau en JavaFX qui vise à simplifier la relation entre patients, médecins et administrateurs autour de trois besoins clés :
- prise de rendez-vous ;
- gestion du suivi médical ;
- centralisation des informations utiles à la consultation.

À l’issue du Sprint 2, le produit a dépassé le stade de simple prototype visuel et dispose déjà :
- d’un espace patient exploitable ;
- d’un espace médecin structuré ;
- d’un espace administrateur de supervision ;
- d’une logique base de données plus réaliste.

L’objectif de ce business plan est de montrer que MeetCare peut être présenté comme un produit crédible, avec une vision, une cible, une proposition de valeur et un modèle économique cohérent.

## 2. Problème identifié
Dans le parcours médical, plusieurs difficultés reviennent souvent :
- difficulté à trouver rapidement un médecin disponible ;
- manque de centralisation des documents ;
- difficulté de suivi entre consultation, facturation et communication ;
- perte de temps pour les médecins dans l’organisation des rendez-vous ;
- manque de visibilité globale pour les administrateurs d’une structure.

MeetCare répond à ce besoin par une plateforme unique regroupant les interactions essentielles.

## 3. Solution proposée
MeetCare propose une solution composée de trois espaces complémentaires.

### Côté patient
- recherche de médecins ;
- consultation du profil médecin ;
- réservation de rendez-vous ;
- consultation des documents ;
- consultation des factures ;
- messagerie ;
- assistance IA.

### Côté médecin
- gestion des disponibilités ;
- agenda ;
- gestion des patients ;
- envoi de documents ;
- création de factures ;
- suivi statistique ;
- profil public.

### Côté administrateur
- supervision des utilisateurs ;
- suivi des rendez-vous ;
- gestion des documents ;
- gestion des factures ;
- statistiques globales ;
- suivi de l’activité.

## 4. Proposition de valeur
MeetCare apporte :
- une meilleure fluidité dans la prise de rendez-vous ;
- une centralisation des échanges et documents ;
- un meilleur confort d’usage pour les patients ;
- un gain d’organisation pour les médecins ;
- une meilleure visibilité pour les administrateurs.

La proposition de valeur peut se résumer ainsi :

**"Une plateforme médicale simple, centralisée et structurée pour mieux connecter patients, médecins et administration."**

## 5. Cibles
Les utilisateurs cibles sont les suivants.

### Cible principale
- patients recherchant une solution simple pour prendre rendez-vous et suivre leurs échanges médicaux.

### Cible secondaire
- médecins souhaitant mieux gérer leurs disponibilités, patients, documents et factures.

### Cible institutionnelle
- structures ou administrateurs ayant besoin d’une vue d’ensemble sur l’activité.

## 6. Analyse du marché
Le besoin existe déjà sur le marché, notamment avec des solutions comme :
- Doctolib ;
- Maiia ;
- Mon espace santé ;
- solutions métiers spécialisées pour cabinets.

Cependant, MeetCare se distingue dans le cadre du projet par :
- une approche pédagogique complète ;
- une volonté de centraliser plusieurs modules dans un même produit ;
- une structuration multi-profils ;
- une logique métier réaliste.

## 7. Modèle économique
Dans une vision produit, plusieurs modèles économiques sont envisageables.

### Option 1 - Abonnement médecin
Le médecin paie un abonnement mensuel pour utiliser :
- l’agenda ;
- la gestion des disponibilités ;
- les documents ;
- la facturation ;
- la messagerie.

### Option 2 - Freemium
- accès gratuit pour les patients ;
- version de base gratuite pour les médecins ;
- options premium payantes pour les professionnels.

### Option 3 - Licence structure
Une clinique ou un cabinet paie une licence pour déployer MeetCare en interne avec un espace administrateur.

### Choix le plus crédible pour la présentation
Le modèle le plus simple à défendre est :

**gratuit pour les patients + abonnement professionnel pour les médecins**

Exemple :
- patient : 0 €
- médecin : 39 € à 79 € / mois selon la formule

## 8. Ressources clés

- équipe de développement Java / JavaFX ;
- base de données MySQL ;
- gestion Git / GitHub ;
- design des interfaces ;
- logique DAO / contrôleurs ;
- documentation produit et technique.

## 9. Activités clés
Les activités essentielles sont :
- développement des fonctionnalités ;
- maintenance de la base de données ;
- tests et stabilisation ;
- amélioration UX/UI ;
- gestion des utilisateurs ;
- documentation ;
- démonstration et soutenance du produit.

## 10. Partenaires potentiels
Dans une logique fictive de développement produit, les partenaires pourraient être :
- cabinets médicaux ;
- structures de santé ;
- professionnels libéraux ;
- hébergeurs de solutions métiers ;
- organismes de transformation numérique dans la santé.

## 11. Avancement produit après Sprint 2
Après le Sprint 2, MeetCare dispose déjà :
- d’un cœur fonctionnel patient ;
- d’un espace médecin riche ;
- d’un espace admin structuré ;
- d’une base de données plus aboutie ;
- d’une logique de réservation plus réaliste ;
- d’une messagerie et d’un assistant IA.

Le produit reste encore à stabiliser, mais il est déjà suffisamment avancé pour être présenté comme une solution cohérente.

## 12. Risques
Les principaux risques identifiés sont :
- instabilité technique après fusion de branches ;
- manque de tests automatisés ;
- complexité croissante de l’application ;
- charge de travail importante sur plusieurs espaces à la fois ;
- risque de dette technique si la stabilisation n’est pas priorisée.

## 13. Perspectives
Pour la suite, les axes de progression sont :
- finalisation du Sprint 3 ;
- amélioration des tests ;
- meilleure robustesse de la messagerie ;
- amélioration des notifications ;
- renforcement de l’expérience utilisateur ;
- meilleure présentation finale du produit.

## 14. Conclusion
Le Sprint 2 montre que MeetCare peut être défendu comme un produit sérieux :
- le besoin est clair ;
- la cible est identifiable ;
- la solution est cohérente ;
- le modèle économique est défendable ;
- le produit a déjà une base fonctionnelle solide.

MeetCare peut donc être présenté non seulement comme un projet académique, mais aussi comme une proposition produit crédible, encore en construction, mais déjà bien structurée.
